# EOS-S05B Command Atelier UX and Client Assurance

**Status:** CEO review draft

## Information architecture

Add `Protection` to Event Command with five purposeful views:

1. Overview — readiness, critical exposures, decisions due and next milestone.
2. Coverage — requirement-to-policy matrix and evidence gaps.
3. Vendors — critical-service roster, evidence and check-ins.
4. Continuity — plans, triggers, activations and incidents.
5. Dossier — governed client/venue assurance edition.

Organisation-level Protection Command is separate: policy catalogue, rule library, clause templates, portfolio renewals and aggregated trends.

## CEO no-blind-spots view

Show: protection readiness by event; expired/expiring evidence; high-consequence unknowns; decisions waiting; concentration risks; untested fallbacks; open incidents; reserve exposure; dossier currency; and what changed since last review. Every count links to the underlying records. Never use a reassuring score without explaining its composition.

## Human hierarchy

Lead with consequence and next action. Use progressive disclosure: headline, why it matters, evidence, decision history, technical metadata. Avoid card soup, raw JSON and UUID-first interfaces. Dates show timezone and relative urgency. Money shows currency and basis. Unknown is a designed state.

## Client assurance dossier

The private client Atelier provides a calm, commissioned summary: protection plan scope, current readiness, approved contingency principles, client decisions required and dated provenance. It must not promise “zero uncovered losses,” guaranteed continuity or insurer payment. Publishing never dispatches it.

## Command Atelier standards

Onyx `#11100F`, ivory `#F5F0E8`, decorative champagne `#B89A62`, functional accent `#8B6E38`; editorial hierarchy; tactile controls; visible focus; pointer on enabled clicks; not-allowed on disabled; text cursor in inputs; reduced motion; no horizontal document scroll at 360px; labelled mobile cards; tablet/desktop/200% zoom; no generic risk-dashboard traffic-light theatre.

## Failure truth

Errors remain action-scoped. Rejected values are not shown as saved. Success receipts state whether data changed. Focus moves to the new result heading once and does not refocus historical results on reload.
