# EOS-S05B Detailed Cursor Pack C Continuity Budget and Experience

**Status:** Ratification draft — not independently executable

## Unit RPC-26 Critical functions

Model event-critical functions and dependencies. Link canonical venue/layout areas, assets and vendor assignments by ID; never copy their truth. Phase-aware requirements must avoid summing phase populations.

## Unit RPC-27 Continuity plan editions

Implement immutable plan editions with recovery objective, maximum tolerable interruption, primary/standby assignments, prerequisites, evidence, decision roles, communication intents and reserve scenario refs. Submit/approve via maker/checker.

## Unit RPC-28 Checkpoint templates and schedules

Model 72h/24h/6h as editable approved templates. Generate event checkpoint instances idempotently in the event timezone. DST/timezone formatting must be tested even though Lagos currently uses WAT. Schedule changes supersede outstanding instances truthfully.

## Unit RPC-29 Check-in evidence

Record confirmed, at-risk or unavailable responses with source and actor. Missed is derived from durable due time and current time. Corrections add lineage. Do not let a reminder delivery receipt count as vendor confirmation.

## Unit RPC-30 Escalation intents

Missed/high-risk checkpoints create internal escalation proposals and optional communication intents. They do not send. Deduplicate repeated evaluation. Show approval requirement, intended recipient/channel and provider status.

## Unit RPC-31 Fallback decision workspace

One screen presents trigger evidence, impact, eligible alternatives, unmet prerequisites, contract implications, Budget variance, reserve need and proposed actions. “Authorise fallback plan” records an authorised plan only. Separate controls for any future booking/payment/dispatch remain unavailable in this slice.

## Unit RPC-32 Activation state machine

Implement transitions in document 07 with expected-version/idempotency enforcement. Authoriser must differ from plan maker for consequential activation. Failure is visible. Cancellation never deletes history.

## Unit RPC-33 Incident command

Build report, triage, timeline, facts/claims/hypotheses, impacts, decisions, action owners, attachments and closure. Life-safety flag presents human emergency protocol copy without false dispatch. Sensitive/personnel/legal fields use central disclosure.

## Unit RPC-34 Post-incident learning

Create proposed model/rule/vendor-indicator changes linked to incident evidence. Adoption is a separate authorised edition. Incident facts remain immutable.

## Unit RPC-35 Risk Budget adapter

Create a single adapter into accepted Budget Intelligence. Inputs follow document 08. Reuse Money, scenario editions, computation trace, idempotency and generated-time semantics. Never create `riskBudgetTotal` as a parallel governing ledger.

## Unit RPC-36 Exposure calculation

Calculate insurance premium assumptions, deductible exposure, contractual retention, continuity reserve and fallback exposure through a closed AST/model edition. Unknown inputs remain unquantified. Tests must fail if an unevidenced price is invented.

## Unit RPC-37 Reserve scenario journey

From a current approved Budget scenario, create a risk successor showing governing values, risk assumptions, variance, basis and sources. A 5% example is explicitly labelled a scenario assumption. Identical request replays same IDs/time; changed input creates immutable successor; stale version is not applied.

## Unit RPC-38 Executive Protection overview

Build CEO no-blind-spots view from document 10. Each headline links to its evidence. Include last-change narrative and “why this is not ready”. Avoid generic cards; use a calm editorial hierarchy and a compact decision queue.

## Unit RPC-39 Event lead workspace

Prioritise actions due, critical gaps, checkpoints, continuity and incidents. Hide organisation-wide sensitive policy details unless required. Provide contextual next steps rather than exposing domain-state jargon.

## Unit RPC-40 Client/venue dossier

Assemble permission-safe dossier edition from explicit approved components. Validate freshness and projection compatibility. Maker submits; distinct checker approves; authorised publisher publishes. Publication creates no communication. PDF/PNG or PDF-only exports show status, full hash, edition/publication, generated time and limitations without truncation.

## Unit RPC-41 Dossier language

Prohibit guarantees and “zero uncovered losses”. Use truthful terms: evidence reviewed as of date, current known gaps, contingency plan prepared, insurer/counsel confirmation required. Client can acknowledge or ask a question without editing staff truth.

## Unit RPC-42 Responsive and accessible interaction

Test 360, 768, 1440 and 200% zoom; no document overflow; touch targets; visible keyboard focus; reduced motion; semantic headings/landmarks; labelled inputs/errors; tables-to-cards; pointer/not-allowed/text cursors. New action results focus once by correlation after verified focus, never `<body>`.

## Unit RPC-43 Experience E2E

CEO full journey; client dossier journey; focused Event Director/risk reviewer/Planner/Auditor/System Administrator deltas. Include discovery, evidence, decision and failure paths. Do not repeat identical journeys by role when permission/API tests cover the delta.
