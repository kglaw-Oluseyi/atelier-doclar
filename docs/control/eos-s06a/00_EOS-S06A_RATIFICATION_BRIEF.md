## 1. Decision requested

Ratify **Atelier Command** as Maison Doclar's governed intelligence-and-execution layer. It gives an authorised operator one conversational surface from which to understand the event, formulate a plan, execute native Event OS work, and—where no safe native integration exists—operate an isolated browser under explicit restrictions.

Atelier Command comprises three co-equal capabilities:

1. **Intelligence:** understand instructions, retrieve event truth, expose ambiguity, reason across investments, roadmap, risks and changes, and construct an executable plan.
2. **Governed native execution:** execute typed Event OS commands through the same permissions, validation, versioning, maker-checker and audit boundaries as a human operator.
3. **Browser-assisted execution:** use a restricted browser only where a native command or approved integration cannot perform the task, with domain allowlists, low-privilege identities, step-level controls and human confirmation for consequential effects.

The principle is:

> **Make the interaction human; make the execution deterministic.**

## 2. What is being ratified

Ratification approves the product contract and build programme—not implementation, deployment, provider activation or real-world execution.

The proposed product includes:

- a role-aware conversational command surface;
- a governed, editable Task Bank covering recurring Event OS capabilities;
- structured interpretation of natural-language instructions;
- intelligence confined to one explicitly selected event;
- a visible plan before execution;
- a typed tool and command catalogue;
- task risk classification;
- automatic, confirm-before-act and maker-checker modes;
- resumable multi-step runs;
- idempotent writes and durable recovery;
- complete human-agent attribution;
- browser-assisted external work under isolation;
- cost, latency and reliability controls;
- replay, evidence, evaluation and independent acceptance;
- eventual integration with AI Discovery, Canonical Event Brief, Investment Intelligence, Roadmap Intelligence, Change Intelligence and Control Tower.

## 4. Three capabilities in practical terms

### Capability A — Intelligence

An operator can ask:

> “What decisions must I make this week to keep Alpha One within its approved investment while protecting guest experience?”

Atelier Command returns evidence-linked facts, assumptions, conflicts, options, recommended decisions, investment impact, roadmap impact, affected owners and confidence. It does not mutate state unless asked and authorised.

### Capability B — Governed native execution

An operator can ask:

> “Prepare the recommended guest-grouping changes, assign owners and submit the seating change for Event Director review.”

Atelier Command resolves the intended event and records, previews the plan, executes registered domain commands, verifies durable results and returns a receipt. It cannot bypass permissions or maker-checker separation.

### Capability C — Browser-assisted execution

An authorised operator can ask:

> “Open the approved venue portal and retrieve the latest room-capacity document.”

If no native integration exists, Atelier Command may operate a dedicated browser limited to that approved domain and low-privilege account. Downloads are quarantined and scanned. Uploads, messages, purchases, terms and account changes require human confirmation at the final step.

## 5. Explicit non-goals

Atelier Command is not:

- a chatbot that merely generates prose;
- an AI with unrestricted database access;
- an autonomous CEO or substitute decision authority;
- a means of bypassing role permissions;
- a hidden background agent making unreviewed consequential decisions;
- a general open-web browsing service;
- a replacement for deterministic Event OS commands;
- a reason to deploy Control Tower prematurely;
- authorised to create real external effects while production is unauthorised.
