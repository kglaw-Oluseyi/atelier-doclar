## 2. What `/app/admin/system` actually reads

Source: `apps/event-os/src/app/app/admin/system/page.tsx`

- `deployedSha()` / Application SHA → `applicationIdentity()` → `currentApplicationIdentity()` in `apps/event-os/src/server/build-identity.ts`
- Resolution: `apps/event-os/src/server/build-identity-resolve.ts`

At **request time** (not from Postgres):

1. **Application / Deployed SHA** = build-embedded `BUILD_APPLICATION_SHA` from `build-identity.generated.ts` when it is a full 40-char SHA (always wins over env). Written at **image build** by `apps/event-os/scripts/write-build-identity.mjs` (`prebuild`), preferring `EVENT_OS_GIT_SHA` then `RAILWAY_GIT_COMMIT_SHA`.
2. **Deployment source SHA** = `process.env.RAILWAY_GIT_COMMIT_SHA` at request time (if full SHA).
3. **Documentation HEAD** = `process.env.EVENT_OS_DOCS_HEAD` at request time (if full SHA). Intentionally separate; currently pinned to `0a0be803…` and does **not** track `origin/main`.
4. **Programme posture** = **static code constant** `EVENT_OS_PROGRAMME_POSTURE` / `formatProgrammePostureLine()` in `apps/event-os/src/server/programme-posture.ts` — a point-in-time governance string baked into the app bundle, not refreshed from DB or Railway.

**Plain statement:** SHA fields are live at request time from **build-time embedded file + process env**, not a Postgres row. They only change when a **new container** is built/deployed (or identity env vars change and a rebuild embeds a new SHA). They are **not** a continuously refreshed “tip of main” probe. Programme posture is a hardcoded snapshot in source.
